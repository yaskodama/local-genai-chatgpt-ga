Level C で何が起きたか

Level C は cell axes が全 6 軸 (paradigm × state_representation × concurrency_model × type_safety × effect_handling × ownership_model) になった結果, セル空間が一気に広がり discard 率が劇的に下がる (62% → 18%):

ほぼ全ての子個体が新セルに着地しているため, 系統樹はもはや 狭い attractor への集約 ではなく 広がり続ける扇 に近い形になります. Level C の 系統樹 を Level A と並べて見ると差が一目瞭然です.

系統樹 HTML では各ノードのホバーで id / gen / operator / composite / cell / parents が表示され, 1 親 → 複数子の分岐, crossover (多親 → 1 子) の合流が 視覚的に確認できます.

「世代」とは

.ga.json の search.generations は 探索 budget の上限です. 実際にどの世代で何が起きたかは, 各実走の lineage.json に generation フィールドとして記録されています. 個別 HTML はその情報を時系列で可視化:

  • composite fitness 推移 — best / mean / worst の各世代値
  • 累積セル数 — MAP-Elites がカバーする (paradigm, type_safety, …) セルの総数
  • 世代ごとの新規発見セル — その世代で初めて埋まったセル
  • operator 内訳 — 各世代で適用された mutation / crossover の種別
  • top elites — 最終的な fitness 上位 10 個体 (どの世代生まれかの欄あり)
